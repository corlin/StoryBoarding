## 目标与边界

用同一组三集连续剧情，验证平台能否以可追踪的成本完成视频生成、声音制作、候选审片、局部返工和成片交付。以下样片为原创测试素材；人物、时长及镜头安排是可调整的工作假设，不代表已验证的最优短剧公式。

优先服务一人或小团队制作连续短剧。第一阶段接通一个视频供应商，并允许外部音视频回传。供应商选择、账号可用性、价格、输入限制、输出质量均需在实际接入前核验；本方案不预设已具备真实视频或配音能力。

既有基础：故事与分镜编辑、角色/场景/道具设定、图片生成、提示词导出、图片历史和项目快照。上述基础不等于视频任务、实际声音对齐、成片导出或完整素材版本恢复已经成立。

## 样片：《第二把钥匙》

类型：都市悬疑。画幅：9:16。每集目标约 45–60 秒，每集先规划 6–8 镜，依据配音与表演实测调整。

人物仅两名：

- 林夏：旧照相馆继承人，浅米色外套，随身携带父亲留下的黄铜钥匙。
- 周明：照相馆前店员，深蓝工作衬衫，知道柜门曾被更换，但起初隐瞒自己参与其中。

场景仅两处：照相馆前厅、后室。三集发生在同一晚。关键道具是一把有缺口的黄铜钥匙、一只锁着的铁盒、一封密封信和一个布袋。

故事事实：父亲把信放入铁盒，周明受托保管；周明换过后室柜门，旧钥匙无法打开柜门，但能打开铁盒。第一集结束前林夏不知道这些；第二集确认周明隐瞒换锁；第三集交代动机并打开信封。信的可读文字采用后期叠加，避免把模型文字渲染当成叙事成立的前提。

| 集数 | 剧情与结尾 | 必测生产能力 |
| --- | --- | --- |
| EP01 钥匙打不开 | 林夏试开后室柜门失败，回前厅质问周明。周明否认知情，却准确说出钥匙有缺口；林夏追问他为何知道。 | 双人正反打、明确说话者、听者反应镜头、实际对白时长、两处空间连贯 |
| EP02 谁换了锁 | 紧接上一集。周明承认换过柜门并拿出布袋；林夏从袋中取出铁盒，用钥匙打开，发现密封信。 | 钥匙从口袋到右手、铁盒关闭到打开、道具持有关系、跨集服装与站位连续 |
| EP03 留给谁的信 | 林夏拿起信，周明解释受托保管的经过。林夏拆信，看到“照相馆留给你，欠周明的钱也请你还清”，两人重新谈判。 | 信封密封到拆开、情绪由怀疑转为复杂理解、对白局部修改、只替换受影响素材、完整三集交付 |

这组样片用于生产验证，不以故事得分、播放量或商业回报作为技术验收依据。

## 最小数据关系

1. Shot 保存镜头意图，并有可引用的修订号。
2. GenerationJob 保存输入修订、参考资产版本、供应商、模型、参数、外部任务 ID、状态、时间和失败原因；重试建立新的尝试记录。
3. Take 保存每次实际产出的媒体、时长、来源任务或外部上传来源、审片状态与退回原因；重生成不得覆盖旧候选。
4. DialogueLine 明确说话者、文本、表演要求、音频版本及实际时长；允许台词跨镜和画外音。
5. EditVersion 保存采用的 Take、入出点、音轨、字幕和导出结果；已确认版本仍能引用当时素材。
6. AssetVersion 保存角色、服装、场景和道具参考版本；场次状态单独记录持有者、开合状态和人物已知信息。

生成输入应保存可复核的快照或哈希及受控引用，不保存明文 API Key。费用原始币种与计量单位必须保留。

## P0 实施顺序

| 顺序 | 交付内容 | 完成证据 |
| --- | --- | --- |
| 1 | 任务与候选素材的数据结构；支持外部视频/音频回传和采用 | 为一个镜头回传两个候选，采用其一后仍可查看另一个 |
| 2 | 一个真实视频供应商适配；持久化提交、查询与恢复 | 页面刷新或客户端断开后仍能追踪任务；重复提交/回调不会创建重复采用素材 |
| 3 | 镜头生产看板与审片 | 能定位待生成、生成中、失败、待审、退回和已采用镜头，并保存退回原因 |
| 4 | 台词、实际音频时长及基础时间线 | 对白说话者明确；时长冲突可定位；允许反应镜头承接跨镜声音 |
| 5 | 基础整集导出与交付版本 | 导出真实 MP4、字幕、素材清单；记录所用素材和剪辑版本，重新打开后可追溯 |
| 6 | 三集样片连续验收与成本复盘 | 三集成片、任务记录、审片记录、成本表和问题清单齐备 |

供应商能力表至少记录：参考图/首尾帧支持、时长和画幅限制、音频支持、异步协议、结果有效期、费用来源及核验日期。不支持的输入必须明确提示，不能静默忽略。外部生成任务取消不应默认解释为退款或未计费。

## 记录方法与指标

配套文件：`short-drama-production-ledger.csv`。每条生产尝试或人工操作单独记录，使用稳定的 episode_id、shot_id、job_id、take_id 关联。人工操作单列，避免同一段工作时间被多个候选重复计算。

- 可用候选率：审片通过的候选数 / 已审候选数，同时报告未审数量。
- 生成成本：所有相关尝试的确认费用，包括废弃和重试。估算与实际费用分开汇总；存在未知费用时，总成本标记为不完整。
- 每分钟已采用成片成本：相关生成总花费 / 对应最终成片时长（分钟）。共享资产开销单列，并披露分摊方式；不同币种未经记录汇率不得相加。
- 人工投入：创作、等待期间的人工处理、审片、返工与剪辑的实际工作分钟；机器等待单列，不当作人工工时。
- 返工：记录触发原因、受影响范围、追加费用和追加人工分钟。
- 完整交付耗时：项目开始到三集确认交付的墙钟时间。

第一轮用于建立基线，不预设没有依据的降本百分比。下一轮用相同类型与长度的样片比较，披露模型和质量要求变化。

## 后续阶段与暂缓项

P1：资产版本依赖、连续性状态、精确配音对齐、局部返工和跨集复用。P2：多人审片、权限、发布规格及实际观看数据回流。

暂缓通用画布、复杂实时协同、更多叙事总分和大规模模型接入。剧情规则作为可解释建议；素材完整性、内容质量、观众表现分别报告。

当前下一项工程工作是 P0-1：任务与候选素材模型及回传/采用流程。开始开发前核对现有鉴权、存储、迁移和项目版本行为，避免破坏已有图片与分镜工作流。
